# Parameter Scenarios & Combinatorics Guide

Comprehensive operational guide for ConnScope's parameter variation engine and combinatorial test matrix generation.

---

## 1. Overview & Purpose

Testing a proxy configuration requires more than verifying default values. Protocol implementations frequently fail under edge-case parameter combinations (e.g. incompatible flow values, non-standard ALPNs, or invalid UUID formatting).

ConnScope includes a combinatorial scenario generator that accepts protocol parameter schemas and systematically constructs test matrices using:
- **Explicit**: Generates a single test case using exact or default parameter values.
- **OFAT (One-Factor-At-A-Time)**: Holds baseline parameters constant while systematically varying one parameter across its allowed values.
- **Pairwise (2-way Combinatorial)**: Tests all pairwise interactions between parameter values, drastically reducing Cartesian explosion while guaranteeing orthogonal pair coverage.
- **Exhaustive**: Computes the full Cartesian product across all parameter values (strictly guarded by size bounds).
- **Invalid Parameter Injections**: Intentionally introduces invalid values to verify that configuration parsers reject malformed inputs gracefully.

---

## 2. Prerequisites & Dependencies

- Python 3.11+ standard library.
- For optional binary validation (`--validate-binary`), the corresponding `xray` or `sing-box` binary must be installed.

---

## 3. Conceptual Model & Terminology

- **Parameter Space**: The set of all valid and boundary values for a given profile family.
- **Baseline Configuration**: The reference parameter set where all values are well-known, safe defaults.
- **OFAT**: Linear scaling strategy testing $O(\sum K_i)$ scenarios.
- **Pairwise**: Quadratic scaling strategy testing $O(K^2)$ interactions.
- **Exhaustive**: Exponential Cartesian expansion testing $\prod K_i$ scenarios.
- **Matrix Bound Guard**: Hard safety ceiling (default: 100 scenarios) that aborts generation if an unplanned combinatorial explosion occurs.

---

## 4. Supported vs. Unsupported Matrix

| Strategy | Strategy Flag | Scenario Growth | Recommended Use Case |
|---|---|---|---|
| Explicit | `--mode explicit` | Exactly 1 | Single-target verification or baseline sanity check |
| OFAT | `--mode ofat` / `--strategy ofat` | Linear ($\approx 5$–$15$) | Rapid isolation of individual parameter regressions |
| Pairwise | `--mode pairwise` / `--strategy pairwise` | Sub-quadratic ($\approx 10$–$35$) | Comprehensive regression coverage across interactions |
| Exhaustive | `--mode exhaustive` | Exponential ($>100$) | Small finite parameter sets with `--allow-exhaustive` |
| Invalid Testing | `--include-invalid` | Appends boundary errors | Verifying negative validation and rejection |

## 5. Step-by-Step Usage & Commands

### Estimating Scenario Counts

Before generating a matrix, inspect the projected scenario count:

```bash
connscope matrix estimate --engine xray --profile vless_tcp_reality --mode ofat
```

### Previewing OFAT Scenarios

Preview the exact parameter variations generated by OFAT:

```bash
connscope matrix preview-parameters \
  --engine xray \
  --profile vless_tcp_reality \
  --strategy ofat
```

### Previewing Pairwise Combinations

Generate orthogonal 2-way combinations:

```bash
connscope matrix preview-parameters \
  --engine sing_box \
  --profile vmess_ws_tls \
  --strategy pairwise
```

### Including Invalid Boundary Tests

Verify that the generator includes negative test cases:

```bash
connscope matrix preview-parameters \
  --engine xray \
  --profile vless_tcp_none \
  --strategy ofat \
  --include-invalid
```

### Validating Generated Parameter Scenarios with Native Binaries

Feed each generated parameter combination directly into the native binary parser to verify engine syntax acceptance:

```bash
connscope matrix preview-parameters \
  --engine xray \
  --profile vless_tcp_reality \
  --strategy ofat \
  --validate-binary
```

## 7. Configuration & Parameter Reference

| CLI Option | Default | Description |
|---|---|---|
| `--strategy` / `--mode` | `explicit` | Matrix generation strategy (`explicit`, `ofat`, `pairwise`, `exhaustive`). |
| `--max-scenarios` | `100` | Safety threshold to prevent unbounded generation loops. |
| `--allow-exhaustive` | `false` | Required flag if an exhaustive matrix exceeds safety limits. |
| `--include-invalid` | `false` | Include intentional negative test variations (e.g. malformed UUIDs). |
| `--validate-binary` | `false` | Pass generated configurations to `xray run -test` or `sing-box check`. |

---

## 8. Error Handling & Common Failure Modes

| Failure Symptom | Cause | Remediation |
|---|---|---|
| `MatrixSizeExceededError` | Exhaustive mode exceeded `--max-scenarios` limit | Switch to `--mode pairwise` or increase `--max-scenarios` with `--allow-exhaustive` |
| `BinaryValidationFailure` | Engine binary rejected a parameter value | Check the specific parameter reported in stderr; verify engine version compatibility |
| `IncompatibleParameterCombination` | Conflicting parameter combination (e.g. flow with non-TLS transport) | The generator automatically excludes invalid combinations; check catalog compatibility rules |

---

## 9. Verification & Evidence Semantics

- **Preview Mode**: Produces Level 0 (`catalogued`) scenario models.
- **Binary Validation (`--validate-binary`)**: Confirms Level 2 (`real_binary_config_validated`) across every generated parameter permutation without establishing live sockets.
